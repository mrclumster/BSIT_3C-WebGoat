SQL Injection (intro)

You exploited a deliberately vulnerable login form using SQL Injection, bypassing authentication without knowing a valid password. This completion is recorded against your account in the database.

Reflection

  • What the vulnerability is

    User input concatenated into a SQL string lets attackers change the query's logic. admin' -- turns the WHERE clause into username = 'admin' and comments out the password check.

  • Why it's dangerous

    Authentication bypass, data theft, data destruction ('; DROP TABLE ...), and full database compromise are all possible.

  • How this app's real login prevents it

    Every query in models.py uses parameter placeholders, so SQLite treats input as data, never as SQL syntax. The same payloads fail on the secure form on the challenge page.

  • Defense in depth

    Even if the query were vulnerable, bcrypt-hashed passwords, generic error messages, CSRF tokens, and rate limiting raise the cost of attack.

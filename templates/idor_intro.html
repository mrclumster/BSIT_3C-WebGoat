What is IDOR?

IDOR happens when an app exposes a direct reference to a record (a database ID, a filename, a UUID) and trusts that the user only requests their own. If the server doesn't check ownership, anyone who guesses or increments the ID can read — or modify — someone else's data.

Your task

  1. You're logged in as profile #1 on a vulnerable endpoint.
  2. The URL pattern is /lesson/idor/profile/<id>.
  3. Visit a profile that isn't yours to complete the lesson.

How to prevent IDOR

  • Always check ownership server-side before returning a record — never trust an ID just because the user knows it.
  • Prefer indirect references — route requests through /me/profile, not /profile/<id>.
  • Use unguessable IDs (UUIDs) when direct references are unavoidable — defense in depth, not a substitute for authorization.

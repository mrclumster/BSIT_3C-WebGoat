Reflected XSS

You injected a script payload into a page that rendered input as raw HTML. In a real victim's browser the script would have executed with the same privileges as the page itself.

Defenses in this app

  • Auto-escape by default.

    Jinja2 escapes every variable rendered with {{'{{ }}'}} unless you explicitly mark it | safe (which we never do for user input).

  • Strict input validation.

    Usernames are restricted to [A-Za-z0-9_.-] — HTML metacharacters never reach the database.

  • HttpOnly cookies.

    Even if XSS were exploited, document.cookie wouldn't expose the session.

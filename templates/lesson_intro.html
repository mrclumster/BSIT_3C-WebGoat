What is SQL Injection?

SQL Injection (SQLi) is an attack where untrusted input is concatenated directly into a SQL query, letting an attacker change the meaning of the query. In a login form, this can bypass authentication without knowing any password.

How a vulnerable login works

A naive login builds its query like this:

SELECT * FROM users
WHERE username = 'USER_INPUT'
  AND password = 'USER_INPUT'

If the input is treated as code instead of data, an attacker can submit ' OR '1'='1 to make the WHERE clause always true.

Hint

Classic payload — in the username field try admin' -- (note the trailing space after --). The -- starts a SQL comment, which makes the rest of the query (including the password check) get ignored.

How this application's real login defends against SQLi

  • Every query in models.py uses parameterized statements (? placeholders) — input is never parsed as SQL.
  • Passwords are hashed with bcrypt — even if a query were bypassed, the stored hash isn't usable.
  • Login errors are generic, so attackers can't tell if a username exists.
  • Rate limiting blocks rapid guessing.

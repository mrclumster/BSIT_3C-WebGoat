Insecure Direct Object Reference

You read another user's profile by changing an ID in the URL. The endpoint accepted any ID without checking whether you owned that record.

Defense pattern

  • Authorize, don't authenticate.

    Login proves who you are. Authorization proves you're allowed to access this specific record. Both are required.

  • Prefer /me/... routes.

    Look up the record by the authenticated session, not by an ID in the URL. Removes the entire bug class.

  • UUIDs as defense in depth.

    Unguessable IDs slow attackers down but never replace a real authorization check.
